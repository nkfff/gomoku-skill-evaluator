# 五子棋 V4.0.5 · 猫猫棋局

V4.0.5 在 V4.0.4 基础上调整真人对局顺序、修复登录状态恢复时序，并将好友房间改为持久化；同时保留 V4.0.4 的管理员后台稳定性修复。**Gunuce** 浏览器本地神经网络难度保持不变。首次加载资源后可离线对弈，优先 WebGPU、WASM 后备，无推理服务器。详细部署与测试说明见 [GUNUCE.md](GUNUCE.md)。

V4.0 是在 V3.4 基础上建立的独立版本，保留 V3.4 入口与数据结构，采用新的暖色视觉系统，并升级 AI 先手、平局奖励、PVP 摇骰子与排行榜荣誉。

## 功能

- 暖象牙白、樱花粉和木质棋盘的统一视觉设计；桌面双栏、手机单栏自适应。
- 保留账号、云端积分、主题商店、猫猫棋子、复盘、残局挑战与随机连珠模式。
- AI 对弈支持玩家执黑或执白；引擎搜索、提示、悔棋、复盘和服务器棋谱验证支持动态颜色。
- AI 对弈平局触发幸运猫猫动画；积分按难度胜局基础奖励的 5 倍结算：新手 50、进阶 150、王者 400。
- 真人 PVP 双方准备后由 Worker 使用 Web Crypto 生成骰子点数；同点自动重掷，胜者执黑先手。双方均确认再来一局后，自动创建新房间与全新对局并重新掷骰；每局独立结算 Elo 与 D1 棋局记录。
- AI 积分榜与真人 Elo 榜前三分别显示「棋圣、棋王、棋宗」。

## 奖励与排行榜口径

| AI 难度 | 胜局基础奖励 | 平局奖励 |
|---|---:|---:|
| 新手 | 10 | 50 |
| 进阶 | 30 | 150 |
| 王者 | 80 | 400 |

平局奖励只作用于标准 AI 对弈；随机模式没有独立积分奖励，真人 PVP 仍按 Elo 和棋规则结算，避免通过协商和棋刷取 AI 竞技积分。AI 积分榜使用累计竞技积分，消费积分不改变排名。

## 部署前要求

V4.0 复用原有 Cloudflare V2/V3 Worker、D1 数据库与 PVP Durable Object。部署前：

1. 备份 gomoku-v2 D1 数据库。
2. 确认 Supabase URL、Cloudflare API Token、Account ID 与 D1 ID 已配置为 GitHub Actions secrets。
3. 先应用 migrations/ 下所有未执行迁移，再部署 V2 与 V3 Worker。
4. 确认 V2 Worker 返回版本 4.0.0，V3 Worker 返回版本 4.0.0。
5. 使用两个账号验证 PVP 摇骰子、同点重掷、双方颜色一致、对局结算和 Elo 更新。
6. 使用登录账号分别测试三种 AI 难度的平局奖励、断网重试和重复提交，确认每局只入账一次。

真实部署状态以 GitHub Actions 和 Cloudflare Worker 实际响应为准；不能仅凭前端页面显示认定云端结算成功。

## V4.0.1 状态栏主题对比修复（2026-11-03）

- 棋盘状态栏背景改为当前棋盘主题的 `--surface`，状态文字使用 `--heading`，辅助文字使用 `--muted`，避免暗夜星河、曜金等深色主题出现浅底浅字。
- 经典、翡翠、暗夜星河、樱花庭院、猫咪咖啡馆、曜金六种主题均通过状态文字与背景的 WCAG AA 对比度（至少 4.5:1）回归测试。
- 更新 Service Worker 缓存版本及离线资源 SHA-256；不修改 AI、积分结算、账号、Worker 或 D1 数据结构。


## V4.0.2 好友 PVP 连续对局与 3D 骰子（2026-11-03）

- 对局结束后出现「再来一局」与「重新匹配」两个操作。
- 「再来一局」采用双方确认机制：一方发起后，对手看到「接受再来一局」；双方都同意后，服务端创建新的房间与 matchId，清空棋盘和计时器，并重新生成服务端骰子结果。
- 新房间创建期间服务端会锁定再战请求，防止连续点击重复创建；若创建失败，会恢复邀请状态并允许重试。
- 每一局仍独立写入 pvp_matches、独立结算 Elo；不复用上一局棋盘、不重复结算旧对局。
- 「重新匹配」返回好友对战大厅，可创建新房间或输入新的好友邀请码。再战生成的新房间 ID 会保存在当前页面链接中，刷新后可自动恢复；当前版本仍是邀请码好友房间，没有随机匹配队列。
- 摇骰改为 CSS 3D 六面骰子，包含立体旋转、抛起、落定与点数揭晓；保留服务器生成点数和同点重掷规则。
- 不新增 D1 表或迁移；部署时需要重新部署 V3 PVP Worker 与更新 GitHub Pages 前端。
- 回归测试覆盖双方确认、重复请求保护、失败恢复、房间切换与刷新恢复、非房间成员拒绝、3D 骰子页面结构与样式。


## V4.0.2 管理员战绩与排行榜管理（2026-11-03）

- 修复管理员清空账号游戏数据不完整的问题：删除目标账号的 AI 对局会话，清零 AI 胜/负/平记录、竞技积分和账户消费余额。
- 保留账号资料、已购皮肤、真人 PVP/Elo 记录、积分流水及管理员审计历史。
- 新增总场次、胜局数和竞技积分基数编辑；平局数保留，输局数自动按「总场次 − 胜局 − 平局」推算。
- 实时预览原始胜率和排行榜综合积分；保存后刷新用户列表与 AI 排行榜名次。
- 区分账户消费余额 `points` 与竞技积分基数 `earned_points`：调整余额不影响排行榜，调整战绩/竞技积分会改变排名。
- 战绩修改与清空均由 Worker 管理员权限校验，并与审计记录在 D1 批处理中写入。
- 自动化测试覆盖胜率/综合积分计算、非法输入、清空事务和管理员界面反馈。


## V4.0.3 真人对局和棋与终局反馈（2026-11-03）

- 修复提出和棋后对手看不到接受/拒绝按钮的问题：服务端推送包含个性化房间快照的事件，双方实时同步待处理状态。
- 提出方看到「等待对手回应」；对手可明确接受或拒绝。双方同意后服务端判定和棋并完成 Elo 结算；拒绝后清除请求、继续对局。
- 服务端阻止重复提出和棋及覆盖对手的待处理请求；对局落子后，未完成的和棋请求自动撤回。
- 认输、五子连珠、超时、断线超时和和棋均在服务端结算成功后统一广播终局事件。
- 双方均收到结果弹窗；胜者显示胜利文案、段位变化和轻量彩带动画，认输方明确看到「你选择了认输，本局判负」。
- 新增和棋状态转换、拒绝/接受、认输判胜、事件推送和弹窗样式回归测试；不新增 D1 表或迁移。


## V4.0.4 好友房间恢复与骰子动画优化（2026-11-04）

- 创建房间后保存房间 ID、邀请码与当前账号绑定的恢复信息；房主刷新页面后自动恢复原房间，不会被误判为新玩家。
- 加入房间的好友同样保存房间 ID；刷新、误关闭页面或重新打开页面后，双方均可恢复到原房间，服务端重新校验账号是否为房间成员。
- 即使本地会话记录丢失，也会按当前登录账号向服务端查询最近的等待中、准备中或进行中的房间；支持同账号换设备恢复。 邀请链接会限定查询对应房间，未加入该房间的好友不会被自动带入。
- 后端邀请码加入接口改为成员幂等恢复：房主或已加入的好友再次输入同一邀请码时，返回原房间状态，不会重复占用房间名额；非成员仍不能进入已满或已开始的房间。
- 修复快速刷新时旧 WebSocket 的关闭事件晚于新连接到达、错误把玩家标记为断线的竞态；同一账号只要还有有效连接，就保持在线状态。
- 骰子动画仍使用原有 CSS 3D 六面骰子与服务端随机点数；首次新对局正常播放，刷新/重连时直接展示已揭晓的最终点数，不重复播放整段动画。
- 「再来一局」继续采用双方确认机制；切换到新房间后自动保存新房间 ID。主动返回大厅或取消房间时清除本地恢复记录。
- 进行中对局沿用现有 60 秒断线宽限与棋钟规则：宽限内重连恢复原棋盘；超过宽限仍按既有断线超时规则结算，但玩家仍可重新进入已结束房间查看结果。
- 不新增 D1 表或迁移；更新 V3 PVP Worker、前端资源 SHA-256 与 Service Worker 缓存版本。
- 新增双方成员恢复、旧 WebSocket 关闭竞态、骰子结果恢复及前端会话持久化回归测试。

- 修复管理员修改总场次、胜局数和竞技积分后，账号资料及排行榜未正确更新的问题。服务端将战绩更新与审计记录放入同一 D1 批处理，并检查实际写入结果后才返回成功。
- 输局数继续按「总场次 − 胜局 − 平局」自动计算；胜率和排行榜综合积分沿用现有规则重新计算，不改变积分算法。
- 管理员保存成功后刷新目标账号资料、管理员账号列表及云端 AI 排行榜；如果写入成功但刷新失败，会明确提示数据已写入及刷新失败原因。
- 管理操作增加进行中、成功、失败和取消提示；审计备注改为可选，留空时自动生成操作原因，避免因未填写备注而无法提交。
- 修复「清空 AI 游戏数据」操作：删除目标账号 AI 对局记录，并将账户消费余额、竞技积分基数及胜/负/平战绩清零。
- 清空范围明确限定为 AI 游戏数据；保留账号资料、皮肤收藏、真人 PVP 房间/对局、Elo 记录、积分流水和管理员审计历史。
- 管理员可以修改或清空自己的 AI 游戏数据，但仍禁止封禁自己的账号。
- 新增 SQLite 集成测试，验证战绩写入、胜率/综合积分计算、清空结果及皮肤/PVP/Elo/审计数据保留；Node 自动化测试与部署检查通过。
- 不新增 D1 表或 migration；更新前端离线缓存版本，避免浏览器继续使用旧版管理员脚本。
- 本次修复已合并并部署，用户完成线上测试并确认稳定。[修复 PR #45](https://github.com/nkfff/gomoku-skill-evaluator/pull/45)。


## V4.0.5 真人 PVP 掷骰先行、登录恢复与房间持久化（2026-11-04）

- 真人对局界面将 3D 骰子区域移动到棋盘之前；修复 CSS 覆盖 HTML `hidden` 属性的问题，掷骰动画与结果揭晓期间棋盘真正隐藏，结果揭晓后再显示棋盘。
- 账号模块导出初始化完成信号；PVP 恢复、创建和加入操作先等待 Supabase 完成 `getSession()`，不再把尚未初始化的客户端误判为未登录。
- 登录状态变化通过统一事件通知 PVP；用户先打开房间链接、再登录时会自动恢复，不需要刷新第二次。检测到房间链接或成功恢复房间时，页面会自动切换到 PVP 标签。
- 房主与好友加入后都保留邀请码、房间 ID 和本地恢复记录；通过邀请码恢复时，服务端仍会核验当前登录账号是否属于该房间。
- 房间不再因 24 小时等待超时自动失效；房主关闭网页、刷新或暂时离线不会销毁房间。房主只有主动点击「取消房间」才会关闭等待/准备中的房间。
- 旧版等待中/准备中房间的过期时间不再被新 Worker 检查；只要未被旧版本提前标记为 expired 或被房主取消，部署后仍可继续加入和恢复。
- 对局进行中仍保留 60 秒断线宽限与棋钟规则；房间持久化不代表暂停比赛计时，超时结算规则不变。
- 不新增 D1 表或迁移；更新 PVP Worker、Durable Object、账号模块、PVP UI、页面结构、主题 CSS、离线资源哈希与 Service Worker 缓存版本。
- 自动化回归覆盖登录初始化等待、登录后自动恢复、双方邀请码恢复、持久化房间与取消规则、骰子区域先于棋盘以及隐藏棋盘的 CSS 行为。
- 再来一局采用明确的邀请确认流程：邀请方发起后，对方收到浮动弹窗，可选择接受或暂不继续；拒绝后服务端清除待处理邀请并通知邀请方，刷新或重连时仍会根据房间状态恢复待处理邀请。
