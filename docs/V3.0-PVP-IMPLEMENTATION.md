# V3.0 PVP implementation notes

**Status:** initial backend foundation in progress. V2.2 remains unchanged.

## Scope for this branch

- Friends-only rooms using an 8-character invitation code.
- Standard 15x15 Gomoku, no forbidden moves; black starts.
- Server-authoritative move validation, clocks, resignation and draw agreement.
- Cloudflare Durable Objects for live room state and WebSockets.
- D1 tables isolated under the pvp_* prefix.
- Separate Elo rating starting at 1000; AI points and AI leaderboard are not modified.
- One active PVP match per account; each player has 10 minutes, no increment.
- Room invitation expires after 24 hours; reconnect grace period is 60 seconds.
- Elo placement is shown as "定级中" for the first 10 rated matches.

## New files

- src/pvp.js: deterministic PVP rules, clock accounting, Elo and rating tiers.
- worker/pvp-room.js: Durable Object room state, WebSocket protocol, match start and result settlement.
- worker/v3.js: V3-only API router, Supabase JWT verification, invite codes, one-time WebSocket tickets, history and leaderboard APIs.
- migrations/0003_pvp.sql: additive PVP schema.
- wrangler.v3.toml: separate Worker and Durable Object deployment configuration.
- test/pvp.test.js: PVP rules and Elo tests.
- .github/workflows/v3-pvp-tests.yml: automated syntax, tests and SQLite migration validation.

## Local verification

Run these commands from the repository root: npm install, npm run check, npm test.

The CI workflow also applies all SQL migrations to an in-memory SQLite database. This checks SQL syntax and table creation; it is not a live Cloudflare integration test.

## Deployment prerequisites

1. Create a **separate** Cloudflare D1 database named gomoku-v3; do not point this config at the V2.2 database for the initial rollout.
2. Replace REPLACE_WITH_V3_D1_DATABASE_ID in wrangler.v3.toml with the new database UUID.
3. Configure SUPABASE_URL as a Worker secret. FRONTEND_ORIGIN is already set for GitHub Pages.
4. Deploy the V3 Worker using the wrangler.v3.toml config.
5. Apply migrations to the V3 database using the wrangler.v3.toml config.
6. Verify /api/health reports pvpConfigured: true and databaseConfigured: true before wiring up the V3 frontend.

The frontend UI, live two-account end-to-end test, abuse rate limiting, and production deployment are not yet complete. Do not describe this branch as a finished or deployed V3 release.
